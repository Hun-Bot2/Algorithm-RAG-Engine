# Independent research review (checkpoint 3 conditional acceptance)

This review covers the checked-in research implementation, captured-source and preservation receipts, and the actual statement baseline, evaluation and compression runs as of 2026-10-16. It accepts the measured checkpoint 3 pipeline and geometry comparison conditionally on its stated scope. It does **not** establish relevance quality, learner benefit, live browser use, or deployment.

## Frozen baselines and methods

- `preservation.v1.json` independently streamed and checked SHA-256 for all **191** files in `research/statements/BASELINE-PRESERVATION.v1.json`; all remain byte-identical. The protected manifest hash is unchanged. The frozen label file remains at **3,647** distinct pairs: 2,886 non-null judgments and 761 abstentions. These are earlier AI-reviewed, title-pooled judgments, not statement-grounded human gold; nulls remain unknown.
- The corpus preserves original identities, text hashes, native duplicate alternatives and source metadata. Its Codeforces and AtCoder matched cohort is shared by statement TF-IDF and pinned MiniLM. Token windows pass source token IDs through the tokenizer with overlap, and the tests check reconstruction of the original token sequence. AtCoder tags remain missing; tag-only and hybrid cross-platform ranking are explicitly blocked rather than silently imputing tags.
- Evaluation computes K=10/20/50 judged coverage, judged-only observed precision and bounds for unknowns, common-explicit-judgment nDCG, query-bootstrap uncertainty, hubness and platform diversity. It does not treat unjudged results as negatives. Native difficulty distance is restricted to within-platform comparisons. Review candidates are bounded and labeled as pending, including unverified cross-platform duplicate candidates; no label is auto-assigned.

## Compression code review

- `compress.py` requires a manifest-marked complete `minilm_chunk` 384D baseline and exact SHA-256 matches for the corpus, vectors and baseline Top50 file before it creates output. It compares on the identical sorted corpus, content-hash exclusions, cross-platform mask and stable top-K ranking routine. The original 384D vectors are included as the reference method.
- Centered PCA and **uncentered** truncated SVD are distinct fitted transforms over all corpus vectors; the seeded Gaussian random projection is separate. Every projected vector is L2-normalized, and the transform matrices (and PCA mean) are stored with deterministic NPZ hashes. The receipt marks fitting as transductive; it cannot establish out-of-sample behavior. Neighbor overlap is a geometry diagnostic, not relevance quality.
- The random projection in `run()` is currently skipped when the **PCA** numerical rank is below a target dimension. Random projection itself has no PCA-rank requirement, so that gate is conservative and can underreport a valid random-projection comparator on rank-deficient inputs. It does not affect the anticipated full-rank corpus; the actual rank must be inspected after the 384D run. If rank is low, revise that gate and its tests before interpreting RP coverage.
- Timings are local process measurements, not device or service latency. Peak RSS is process-wide high-water memory; the reported per-method incremental difference is only a lower bound on method-specific memory, since earlier peaks persist.

## Actual baseline, evaluation and compression

- I independently rehashed the private source, corpus, 384D MiniLM vector file, Top50 file and pinned model manifest against `statement-run-v1/manifest.json`; all matched. The corpus has **9,424** unique sorted keys (8,101 Codeforces; 1,323 AtCoder). The 384D matrix is finite float32 and unit normalized (norm range 0.99999988–1.00000012). Token lengths sum to 4,410,241 and independently imply **22,034** nonoverlapping 254-content-token windows, matching the run receipt. Each of the 9,424 baseline queries has 50 unique targets on the opposite platform, with no equal content-hash target. This checks saved outputs and stated chunk counts; it does not independently rerun the 336.6-second embedding computation or prove every publisher description includes all source-page sections.
- The baseline receipt reports **336.6 seconds** and **1,608,040,448 bytes** process peak RSS for the five-method matched retrieval run. `minilm_chunk` is the completed original 384D statement baseline. Statement word and character TF-IDF, MiniLM title, and MiniLM title-plus-prefix are comparators on the same corpus. The latter truncates at 256 tokens and is not a full-statement embedding. Tag/hybrid methods are blocked because cross-platform tag coverage is absent; permitted LeetCode statements are zero.
- The evaluation receipt hashes the same corpus and five Top50 runs, the frozen labels and taxonomy; every hash matched its current file. Across all five methods at K=10/20/50, **zero slots are judged** by the frozen labels. I independently intersected the 3,647 historical pairs with the new corpus and found no pair with both endpoints present. Therefore observed precision and nDCG are unavailable, with precision bounds [0, 1]. The 1,000-item general review queue and 200-item possible cross-platform semantic-overlap queue are pending judgments, with no auto-label or merge. Their public receipt fields contain IDs, ranks, strata and null label status, not statement text, title or samples.
- Compression ran **after** the completed 384D baseline. I checked its manifest link plus every method's saved vector, ranking and transform hash: **40/40** checks passed. The original 384D Top50 overlap is 1.0. Both centered PCA and uncentered SVD have numerical rank **382**, so the prior random-projection rank-gate concern does not limit the tested 256/128/64 dimensions. At 256D, Top10 neighbor overlap with the original is **0.973875** for uncentered SVD and **0.679499** for centered PCA; these are neighborhood-preservation diagnostics only. All projected vectors are finite and unit normalized. Fit is transductive over every corpus row, and timings are local process measurements.

The focused suite passed: `.venv/bin/python -m unittest discover -s research/algorithm_system -v` ran **51 tests**. The public aggregate receipts `statement-baseline.v1.json`, `evaluation.v1.json` and `compression.v1.json` match their private counterparts byte-for-byte. Checkpoint 3 is accepted as a reproducible source-scoped **measurement**, while relevance quality and model promotion remain unsupported until new, independently reviewed statement-cohort judgments exist.
